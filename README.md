# Software texture cache boundary bug

(AI-assisted) A standalone PS2SDK ELF that reproduces the software renderer's
inclusive texture-coordinate boundary bug. All texture data and lettering are
generated by the test; no game files are required.

## Build and run

With PS2SDK installed under `/usr/local/ps2dev`:

```sh
make
../pcsx2/cmake-build-release/bin/pcsx2-qt -elf "$PWD/software-texture-cache-bug.elf"
```

Select **Software** rendering in PCSX2. The test keeps drawing until you stop
emulation. You can also launch the ELF on a PS2 through ps2link:

```sh
ps2client -h 10.0.0.199 execee host:software-texture-cache-bug.elf
```

Reset the console back into ps2link after testing:

```sh
ps2client -h 10.0.0.199 reset
```

For a different SDK installation, set `PS2DEV` and/or `PS2SDK` when running make.

## Expected result

All three panels should display green stripes. With the original software
renderer, only CONTROL is green; REDUCE and EXTEND are black.

| Panel | TEX0.TW / TH | Declared dimensions | Boundary exercised |
| --- | --- | --- | --- |
| CONTROL | 6 / 6 | 64 × 64 | Row 32 is already inside the texture |
| REDUCE | 10 / 10 | 1024 × 1024 | Cache optimization must retain row 32 when reducing the height |
| EXTEND | 6 / 5 | 64 × 32 | Region repeat selects row 32, so the cache must extend the height |

The texture is physically uploaded as 64 × 64 PSMCT32, with TBW=1. Row 32
contains green stripes; all other rows are purple. Every panel uses nearest
sampling and REGION_REPEAT on both axes, with MINU=63, MAXU=0, MINV=0,
MAXV=32. The V transformation `(v & 0) | 32` always selects row 32.
That requires a cache height of at least 33 texels, rounded up to 64.

The old size helpers treated the highest sampled coordinate as though it were
an exclusive bound. They reduced the cache to 32 rows and failed to extend it
when the highest coordinate equalled the dimension. Row 32 was consequently
not populated in the software texture cache.

## Local validation

The ELF was booted in PCSX2 and its GS stream replayed through:

- Original software renderer: CONTROL green; REDUCE and EXTEND black.
- Fixed software renderer: all three panels green.
- parallelGS: all three panels green.
- Vulkan: CONTROL and REDUCE green; EXTEND purple. This is a separate
  discrepancy in the case where region repeat selects a row beyond TEX0.TH.

The ELF subsequently launched successfully on the physical PS2 at
10.0.0.199 after ps2link was restarted. The user confirmed that all three
panels look correct on the console.

Latest official upstream master was also tested directly at commit
`14257cd398e4326443156de7cc7ed9b472c9e29f`:

- Unmodified upstream: CONTROL green; REDUCE and EXTEND black.
- After cherry-picking the fix (`a37467791508dfe9c1ecd2b29900116265663526`):
  all three panels green; all 82 existing core tests pass.

Both builds booted the same ELF in Software mode. Replaying the same captured
GS stream before and after the fix confirmed the result as well. The local
branch is `fix/software-cache-off-by-one-upstream`; it has not been pushed.

`validation/upstream-before-software.png`,

Local captures are in the ignored `validation/` directory, including
